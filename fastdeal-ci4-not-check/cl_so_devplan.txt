━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  FastDeal is a real-estate listing platform built on CodeIgniter 4.
  The codebase is structurally sound — good MVC separation, clean routes,
  proper filter-based auth, Tailwind + Alpine.js on the frontend.

  HOWEVER, there are critical gaps between the current state and a
  "production-ready, trust-inspiring" real estate portal:

  1. Several pages are SKELETON (Agents, Blog, Neighborhoods, Customer)
     — controllers exist but data is static/hardcoded.

  2. The image pipeline is broken in key ways:
     - logo.png is referenced but the /public/assets/images/ folder is EMPTY.
     - Gallery images on the detail page use hardcoded placeholder data.
     - Similar Properties section uses hardcoded IDs (2, 4, 5) — will 404.

  3. The search/filter system on listings is PURELY COSMETIC — it does not
     submit to the server or filter any data.

  4. The Listings page shows a hardcoded "1,245 Properties Found" counter
     and static pagination — both misleading and broken.

  5. CSRF protection is DISABLED globally (commented out in Filters.php)
     — the lead form + newsletter form are unprotected.

  6. The newsletter submit fires an alert() popup — not professional.

  7. forcehttps filter is ENABLED in required filters but the app runs on
     HTTP locally — this may cause redirect loops in production.

  8. No SEO meta tags (description, og:image, og:title) on any page.

  9. The Database is SQLite3 — fine for dev, must be MySQL for production.

  10. No pagination implemented on Listings — just static HTML buttons.

  11. The "About" and "Contact" pages use Unsplash images — fine, but
      the Contact form does NOT actually submit (Pages::contact just
      renders the view — no POST handling, no email, no lead save).

  12. Agent detail page uses fully hardcoded data — not DB-connected.

  13. Blog controller does not query a blog table — static content only.

  14. No 404 / 500 error page templates in the errors/ views.

  15. The `dark:` Tailwind color `dark` is incorrectly mapped to #f8fafc
      (which is a LIGHT color) — this is a major design bug that causes
      text color issues throughout.

  16. Mobile nav uses x-data="mobileMenuOpen" but the body tag renders
      it via renderSection('body_attributes') — if a page overrides
      body_attributes without mobileMenuOpen, the hamburger button breaks.

  17. The main.php layout has a CSS injection bug:
      `<?= $this->renderSection('extra_css') ?>.glass-panel {` — the
      extra_css section is rendered INLINE before the .glass-panel rule,
      which could break page styles if extra_css is empty.

  18. The delete property route uses GET (not POST/DELETE) — a CSRF risk
      and bad REST practice.

  19. Admin settings page says "save to settings table" but saves nothing.

  20. No robots.txt useful content, no sitemap.xml route.

  [BUG-001] CRITICAL — Logo Image Missing
  File    : public/assets/images/ (EMPTY FOLDER)
  Impact  : Logo broken on ALL pages (nav + footer), unprofessional
  Fix     : Add logo.png to public/assets/images/
            OR update nav.php & footer.php to use a text/SVG logo as fallback

  [BUG-002] CRITICAL — CSS Injection in Layout (Newline Bug)
  File    : app/Views/layouts/main.php, Line 51
  Code    : `<?= $this->renderSection('extra_css') ?>.glass-panel {`
  Impact  : When extra_css is not empty, .glass-panel rule is prepended
            with injected CSS — breaks glass card styling
  Fix     : Add a newline + proper separation:
            `<?= $this->renderSection('extra_css') ?>
             .glass-panel { ... }`

  [BUG-003] CRITICAL — CSRF Completely Disabled
  File    : app/Config/Filters.php, Lines 77-79
  Issue   : csrf filter commented out in globals.before
  Impact  : Lead forms, admin forms, login form all unprotected
            (CSRF token IS rendered in views — just never validated)
  Fix     : Uncomment `// 'csrf',` in globals.before
            Ensure all forms include <?= csrf_field() ?>
            (They already do — so this is a 1-line fix)

  [BUG-004] CRITICAL — Similar Properties Section Uses Hardcoded IDs
  File    : app/Views/listings/detail.php, Lines 540, 572, 604
  Issue   : href="listings/2", "listings/4", "listings/5" — hardcoded
  Impact  : Will 404 if those property IDs don't exist in the database
  Fix     : Fetch 3 similar properties in Listings::detail() controller
            and pass them to the view

  [BUG-005] HIGH — Search/Filter Does Not Work
  File    : app/Views/listings/index.php, Lines 47-169
            app/Controllers/Listings.php
  Issue   : Filter sidebar is cosmetic — form has no action="" and
            Listings::index() does not read any $_GET params
  Impact  : Clicking "Apply Filters" does nothing — major UX failure
  Fix     : Add GET form action to filter sidebar pointing to /listings
            Update Listings::index() to accept query params:
            type, listing_type, city, min_price, max_price, beds, baths

  [BUG-006] HIGH — Property Count is Hardcoded
  File    : app/Views/listings/index.php, Lines 29, 179
  Issue   : Shows "1,245 Properties Found" regardless of actual count
  Impact  : Confuses users — shows zero properties but "1,245 found"
  Fix     : Pass $totalProperties from Listings::index() to view
            Use: <?= $totalProperties ?> Properties Found

  [BUG-007] HIGH — Pagination is Static HTML
  File    : app/Views/listings/index.php, Lines 259-281
  Issue   : Page numbers (1,2,3...12) are hardcoded buttons
  Impact  : Only page 1 ever loads — user cannot navigate
  Fix     : Use CI4's built-in Pager library in Listings::index()
            Pass $pager to view and render with $pager->links()

  [BUG-008] HIGH — Contact Form Does NOT Submit
  File    : app/Controllers/Pages.php, Lines 12-16
            app/Views/pages/contact.php
  Issue   : Pages::contact() only handles GET — no POST logic
  Fix     : Add $routes->post('/contact', 'Pages::contactSubmit')
            In contactSubmit(): validate + save to leads table
            Flash success message

  [BUG-009] HIGH — forcehttps Filter Active in Dev
  File    : app/Config/Filters.php, Lines 55-58
  Issue   : 'forcehttps' in $required['before'] causes redirect loop
            when running on localhost HTTP
  Fix     : Wrap in environment check OR remove from required
            and apply only in production via a conditional

  [BUG-010] MEDIUM — Agent Detail Page is 100% Hardcoded
  File    : app/Views/agents/detail.php
            app/Controllers/Agents.php
  Issue   : Agent photo, name, email, listings are all static HTML
  Impact  : Not reflecting real agents from the users table
  Fix     : Phase 2 — Create AgentProfile model or use users table,
            pass agent data from controller

  [BUG-011] MEDIUM — Newsletter Submit Shows alert() Popup
  File    : app/Views/partials/footer.php, Line 73
  Issue   : onsubmit="event.preventDefault(); alert('...')"
  Impact  : Terrible UX for a premium real estate brand
  Fix     : Add /newsletter/subscribe POST route
            Show inline success message (Alpine.js state)

  [BUG-012] MEDIUM — "dark" Color Token is Light (#f8fafc)
  File    : app/Views/layouts/main.php, Line 90
  Code    : dark: '#f8fafc'  ← this is slate-50 (almost WHITE)
  Impact  : Any element using text-dark or bg-dark will be barely visible
            or white on white. CTA button "bg-white text-dark" = white text
  Fix     : Rename to 'paper': '#f8fafc' OR correct dark to '#0f172a'

  [BUG-013] MEDIUM — Mobile Nav Body Attributes Can Break
  File    : app/Views/layouts/main.php, Line 104
  Issue   : body_attributes section renders 'x-data="{ mobileMenuOpen }"'
            but this can be overridden by child views without mobileMenuOpen
  Fix     : Always declare mobileMenuOpen in the layout body tag directly,
            allow child views to EXTEND it rather than replace

  [BUG-014] MEDIUM — Delete Property Uses GET Route
  File    : app/Config/Routes.php, Line 42
  Code    : $routes->get('listings/delete/(:num)', ...)
  Issue   : GET requests should never modify data — CSRF bypass risk
            A scraped URL or email link could delete properties
  Fix     : Change to POST with a confirmation form
            Use CSRF token for every destructive admin action

  [BUG-015] MEDIUM — Property Images Use base_url() Incorrectly
  File    : app/Views/home/index.php, Line 108
            app/Views/listings/index.php, Line 211
  Code    : base_url($prop['main_image'])
            main_image is stored as "uploads/properties/filename.jpg"
            This works IF base_url ends with /
            But if base_url = "http://localhost:8080" (no trailing slash),
            the URL becomes http://localhost:8080uploads/... (broken)
  Fix     : Ensure .env has trailing slash in baseURL
            Use base_url('uploads/...') pattern consistently

  [BUG-016] LOW — Blog Has No Database Table
  File    : app/Controllers/Blog.php
  Issue   : Blog::index() and Blog::detail() render static views
            No BlogPost model, no migration for blog_posts table
  Fix     : Phase 2 — Create blog_posts migration + BlogModel
            Or keep static but at least make it look populated

  [BUG-017] LOW — Neighborhoods Page is Nearly Empty
  File    : app/Controllers/Neighborhoods.php
            app/Views/neighborhoods/
  Issue   : Controller is 166 bytes — likely just returns a view
  Fix     : Phase 2 — Create neighborhoods table + model
            Display cities: Surat, Ahmedabad, Mumbai etc.
            Link to filtered listings by city

  [BUG-018] LOW — Customer Dashboard is Placeholder
  File    : app/Controllers/CustomerController.php (174 bytes)
  Issue   : After a user logs in as non-admin, they get a blank dashboard
  Fix     : Phase 2 — Show saved properties, submitted enquiries,
            account settings

  [BUG-019] LOW — No SEO Meta Tags
  File    : app/Views/layouts/main.php
  Issue   : No <meta name="description">, no og:image, no og:title
  Fix     : Add meta description section in layout

  [BUG-020] LOW — Error Views are Empty
  File    : app/Views/errors/
  Issue   : Custom 404/500 pages likely showing CI4 default errors
  Fix     : Create branded 404.php and production_error.php in errors/
